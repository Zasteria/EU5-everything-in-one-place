# Can this country actually be raised to kingdom rank right now?
#
# HRE members are held below kingdom by the Empire itself, but the block is
# CONDITIONAL: international_organizations/hre.txt:125-133 wraps
# `block_from_change_to_kingdom_rank` in a potential_trigger that lifts it
# under two of the rank game rules. Our formables used to test membership
# alone, which refused the rank in cases the engine would have allowed, so
# a player who had deliberately turned rank restrictions off still formed a
# kingdom-titled country stuck at duchy rank.
#
# Empire rank is NOT covered by this trigger. `block_from_change_to_empire_
# rank` sits in hre.txt's unconditional modifier block (line 120), but it
# only governs the player's rank BUTTON (country_ranks/00_default.txt:46-48):
# set_country_rank_effect is not bound by the rank's allow, and vanilla's
# Germany formable grants empire rank by effect to sitting members
# (GER_f's form_effect in 00_formable_countries.txt). Whether a formable inside the
# Reich takes empire rank is therefore a design call per formable
# (2026-08-24): the Danubian Monarchy keeps kingdom rank when it stays,
# because the one Empire inside the Reich is the Reich.
nd_can_take_kingdom_rank = {
	OR = {
		NOT = { is_member_of_international_organization = international_organization:hre }
		has_game_rule = no_rank_restriction
		has_game_rule = rank_restriction_by_numbers
	}
}

# Is the Reaction of the Reich enabled in the lobby?
#
# Read at every activate_situation site for nd_dnm_reaction_of_the_reich.
# The rule governs the EMPIRE'S ANSWER only: a Monarchy that breaks with
# the Reich still sweeps its imperial land out and still takes empire rank,
# and both Danubian disasters gate on nd_dnm_formed and on their own rule
# (nd_dnm_crises_are_enabled below) rather than on the situation, so the
# internal arc (the Nationalities Question, the Pragmatic Sanction) is
# untouched by switching this off. Read at every activation
# site: the break option of nd_dnm.52, the break interaction, and the
# monthly departure catch, all through nd_dnm_break_with_reich_effect.
nd_reich_reaction_is_enabled = {
	has_game_rule = nd_reich_reaction_enabled
}

# Is the Succession of the Danube enabled in the lobby?
#
# Read at both activation sites of nd_danube_succession: the world-spark
# watcher (nd_dnb_spark_watch) and the pact interaction's potential
# (nd_dnb_propose_the_pact). Off means the question never opens, which is
# the switch that stops the situation-made AI Danubian Monarchy: the
# situation's ending force-forms DNM for an AI holder
# (nd_dnb_proclaim_or_offer). The other AI road is the AI Forms Nations
# pulse (99_nd_on_actions.txt), which lists DNM since 2026-08-25 and is
# governed by its own rule. nd_reich_reaction_is_enabled above is NEITHER
# switch; it only decides whether the Empire answers a Monarchy that
# already exists.
nd_danube_succession_is_enabled = {
	has_game_rule = nd_danube_succession_enabled
}

# Do the Danubian Monarchy's two disasters, the succession question that
# leads into one of them, and the forewarning event nd_dnm.48 run in this
# campaign? Reads nd_dnm_crises_rule and nothing else.
#
# Written as "not disabled", where the two triggers above ask for the
# enabled setting. The rule is new in a mod with campaigns in progress, and
# no file says what has_game_rule answers for a rule a save has no value
# for. Asked this way, a save that carries no value keeps the disasters it
# always had, whichever way the engine treats it. Vanilla reads a rule by
# its off setting the same way (scripted_triggers/game_triggers.txt:37-38,
# game_has_missions_enabled).
nd_dnm_crises_are_enabled = {
	NOT = { has_game_rule = nd_dnm_crises_disabled }
}
