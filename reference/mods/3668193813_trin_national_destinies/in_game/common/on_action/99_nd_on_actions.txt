# ==========================================================================
# WHY THESE HOOKS LOOK INDIRECT
#
# An on_action's `effect` is a SINGLE-VALUE field. When two files declare
# `effect` for the same on_action the engine keeps one and silently discards
# the other, logging only "There is more than one 'effect' defined using most
# recent: <file>". Vanilla never does this: across all 164 vanilla on_actions
# there are zero cases of two files declaring the same field. Paradox avoids
# it with a chain: ai_personalities_setup.txt adds
# `on_actions = { on_ai_personalities_game_start }` to on_game_start rather
# than a second `effect`.
#
# This file used to declare `effect` directly on `on_game_start` (colliding
# with _hardcoded.txt) and on `on_four_yearly_check_for_script` (colliding
# with country_four_yearly.txt). Our file sorts before both alphabetically, so
# vanilla parsed last and won, and BOTH of our effects were dropped: no
# destiny trees for the 20 game-start tags below (the Austria/Bohemia/Poland
# Workshop reports) and no BYZ achievement gate. It also used
# `on_country_yearly_pulse`, which is not an engine on_action at all. The
# name appears nowhere in vanilla, so it was never called and the DNM
# succession chain never fired.
#
# Rules for editing this file:
#   * Before declaring a field on a vanilla on_action, check that no vanilla
#     file already declares that same field on it. `eu5-validate --checks
#     on_actions` enforces this.
#   * Engine periodic country hooks are `monthly_country_pulse`,
#     `biyearly_country_pulse`, `yearly_country_pulse`,
#     `four_yearly_country_pulse` (no `on_` prefix). An `on_`-prefixed pulse
#     name is almost certainly invented and will never fire.
#   * Slot ledger as of 2026-09-10: WE hold monthly_country_pulse.effect
#     (bootstrap + DNM chain + France unlock + Danube spark watch + AI
#     formables),
#     on_four_yearly_check_for_script.on_actions (BYZ achievement) and
#     on_new_ruler.on_actions (Danube succession checkpoint). Still free:
#     biyearly_country_pulse.effect, on_country_specific_pulse.{effect,
#     on_actions}. Re-verify against vanilla after every patch.
# ==========================================================================

# Fire formation events at game start for tags that exist as already-formed countries.
# Without this, players starting as e.g. Bohemia never get their destiny tree because
# the formation event (which sets nd_TAG_formed) only fires when the country is formed
# from an unformed state.
#
# Two deliberate details, both from players repeatedly reporting the destiny tree
# missing for game-start tags (Workshop: Austria 2026-06-13, Bohemia 2026-07-16,
# Bohemia + Poland 2026-07-27) even though this handler was supposed to cover them:
#
#  1. The `_formed` variables are set HERE, not left to the event's options. Destiny
#     advance visibility keys off nd_TAG_formed, so tying it to the player answering
#     a popup makes an entire content tree depend on a popup being delivered. Setting
#     it directly makes the tree appear whatever happens to the event.
#  2. The event fires on a 3-day delay rather than during game setup, so it arrives in
#     a running game with a live event queue. The option still grants the timed
#     modifier and sets nd_TAG_path_*, which the destiny branches need.
#
# Setting the variable twice (here and again in the event option) is harmless: the
# guard below has already been evaluated, and set_variable is idempotent.
#
# The formation event's own fire-guard is a SEPARATE variable, nd_TAG_e1_done,
# not nd_TAG_formed. Keeping them separate is what lets point 1 above stay true.
# Formation events moved off fire_only_once on 2026-08-06 because it is per
# CAMPAIGN, so a game-start tag burned the event for every later former
# (Workshop report ewobmrk, Tibet). Had that guard reused nd_TAG_formed, this
# pre-set would make the queued event fail its own trigger, and restoring the
# event would have meant deleting the pre-set and putting destiny visibility
# back at the mercy of a delivered popup: the exact bug points 1 and 2 exist to
# prevent.
#
# DAH and YUA are the exception: their nd_<tag>.1 is an advance-gated DHE, not
# a formation event, so nothing would ever set their variables. They keep the
# pre-set and lost the day-3 call, which always failed the advance trigger.
#
# HOOK: monthly_country_pulse.effect (its `on_actions` is vanilla-owned).
# Was on_game_start.effect, which vanilla discarded. Runs per country per

#
# Cost of moving off game start: the event now arrives within the first
# month rather than on day 3. Upside: because the flag lives in the save,
# an EXISTING save that never got bootstrapped is repaired on load.

# Achievement-triggered formation events for starting+formable overlaps.
# The country-start player can't use the formable button (you can't form
# what you already are), so we check four-yearly whether they have reached
# the formable's imperial-reach allow conditions. When met, fire the
# formation event chain. Variable check prevents re-firing.
#
# HOOK: vanilla owns on_four_yearly_check_for_script.effect, but its
# `on_actions` field is free, so we chain to our own on_action exactly as
# ai_personalities_setup.txt does. Cadence and scope are unchanged; the
# effect simply now runs instead of being discarded.
on_four_yearly_check_for_script = {
	on_actions = { nd_on_four_yearly_check }
}

nd_on_four_yearly_check = {
	effect = {
		# BYZ achievement: 3-city Komnenian core (Constantinople + Athens +
		# Iznik). Forces game-start BYZ to actually reconquer territory
		# (meaningful imperial recovery beyond the starting position)
		# before earning our formation event and content. Preserves the
		# vanilla 1.2 DLC's stabilization-focused early game.
		if = {
			limit = {
				exists = c:BYZ
				NOT = { c:BYZ = { has_variable = nd_byz_formed } }
				c:BYZ = {
					# Orthodox is the canonical restoration, but d008 lets BYZ
					# restore Hellenism (the old Roman religion). Accept both so a
					# Hellenic revival isn't locked out of the formation event;
					# nd_byz.1 offers a religion-appropriate choice for each.
					OR = {
						religion = religion:orthodox
						religion = religion:hellenism_religion
					}
					owns = location:constantinople
					owns = location:athens
					owns = location:iznik
				}
			}
			c:BYZ = { trigger_event_non_silently = nd_byz.1 }
		}

		# SCRIPT-FORMED TAG REPAIR (2026-08-08, Workshop report on JAP).
		#
		# Vanilla can create a country WITHOUT the player pressing the
		# formable button: `form_country = formable_country:X_f` appears at
		# 25 sites across situations, DHE chains, peace treaties and generic
		# actions. sengoku.txt forms JAP from the shogunate leader when the
		# Sengoku Jidai ends; rise_of_the_ottomans forms RUM; flavor chains
		# form MOL, AYU, TUS and others.
		#
		# The formation markers are now set in each form_effect, which
		# covers this as long as form_country runs form_effect. That has not
		# been confirmed against a live game, and the failure is silent and
		# total: the tag keeps every advance gated on its marker locked
		# forever, which is exactly what was reported. So this repairs the
		# state independently, on a cheap four-yearly cadence, for the 13
		# mod tags vanilla can form by script.
		#
		# Self-healing by design: a save already broken by this bug is
		# repaired within four years of loading. Costs nothing when the
		# markers are set, because every branch tests for their absence.
		# The bootstrap block on monthly_country_pulse cannot do this job:
		# it is wrapped in a global run-once flag, so it fires on the first
		# pulse of the campaign, centuries before any of these tags exist.
		nd_repair_script_formed_effect = { TAG = ADU LTAG = adu }
		nd_repair_script_formed_effect = { TAG = BNG LTAG = bng }
		nd_repair_script_formed_effect = { TAG = CHI LTAG = chi }
		nd_repair_script_formed_effect = { TAG = DLH LTAG = dlh }
		nd_repair_script_formed_effect = { TAG = GBR LTAG = gbr }
		nd_repair_script_formed_effect = { TAG = IRE LTAG = ire }
		nd_repair_script_formed_effect = { TAG = JAP LTAG = jap }
		nd_repair_script_formed_effect = { TAG = LAT LTAG = lat }
		nd_repair_script_formed_effect = { TAG = MOL LTAG = mol }
		nd_repair_script_formed_effect = { TAG = PGR LTAG = pgr }
		nd_repair_script_formed_effect = { TAG = PRU LTAG = pru }
		nd_repair_script_formed_effect = { TAG = RUM LTAG = rum }
		nd_repair_script_formed_effect = { TAG = SWI LTAG = swi }
		nd_repair_script_formed_effect = { TAG = TUS LTAG = tus }

		# The event-formed tags. Their nd_<tag>.1 is an advance-gated DHE
		# rather than a formation event, so they take the marker-only
		# variant: setting the variable is the entire fix, and calling the
		# DHE would just fail its own trigger.
		#
		# Until 2026-08-08 none of these had a formable file at all, so the
		# only writer of nd_<tag>_formed was that DHE's options, behind an
		# age-3 advance. The bureaucracy grant in each tag's auto_modifier
		# reads that variable, so four bureaucracies per tag sat unreachable
		# for most of a campaign. They now also set the markers in
		# form_effect; this sweep is the belt to that pair of braces, and for
		# MLC it is the only thing that works at all.
		nd_repair_script_formed_marker_only = { TAG = AYU LTAG = ayu }
		nd_repair_script_formed_marker_only = { TAG = BAH LTAG = bah }
		nd_repair_script_formed_marker_only = { TAG = DAH LTAG = dah }
		nd_repair_script_formed_marker_only = { TAG = MLC LTAG = mlc }
		nd_repair_script_formed_marker_only = { TAG = MTM LTAG = mtm }
		nd_repair_script_formed_marker_only = { TAG = YUA LTAG = yua }
	}
