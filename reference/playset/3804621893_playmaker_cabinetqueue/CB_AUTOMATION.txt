Auto CB prototype
Choose Auto CB beside a target, then choose the CB. Multiple different targets can run concurrently; each target has one independent job stored in player-owned maps. Adding or cancelling a target does not clear other jobs.
The target preview uses installed native creation conditions, Religious War unlocks, and excludes CB types already owned against that target. Eligibility and duplicates are checked again before dispatch. A matching CB acquired while waiting retires the job and recalls only an automation-owned spy mission.
The scheduler starts native spy missions individually, letting their networks grow in parallel. Native dialogs are serialized through one dispatcher so simultaneous ready targets cannot mix CB/province selections. It reads the actual actor-to-target spy network, floors it, and requires at least 20. Native action availability also gates dispatch: if no diplomat is available, the job waits and is reconsidered automatically.
Spy recall explicitly accepts only the armed Cancel Build Spy Network confirmation. Jobs are removed only after the native relation reports the spy mission gone. Once the chosen CB starts, its target's spy mission is recalled even if it was already running before Auto CB. Cancelling an unstarted job still preserves player-started spies. Cancel target applies to the target currently shown and is briefly disabled while the dispatcher owns a native action.
Native CB costs, timing, and province selection still apply. A timed-out CB submission is shown as failed for that target; cancel it and check native requirements. A pre-click availability race releases the dispatcher with a short retry delay. Old single-target jobs migrate once on UI load.
Static checks cover all 58 mappings, independent jobs, duplicate gates, threshold boundary logic, serialized election guards, recall confirmation/completion ordering, GUI expressions, and structure. In-game verification is still required for native network values, multiple simultaneous jobs, and confirmation dialogs.

Window behavior: only an explicit Auto CB click opens the custom window. Background timeouts record their status silently without changing the selected target. Confirmed native CB creation closes the custom window and the automation-owned native picker; the next job waits briefly for that close to finish.

Creation-start detection now uses the native is_creating_cb_of_type game-state trigger for the exact chosen type and target, independent of outliner relation updates. It hands the same dispatcher directly to spy recall. Completion closes the native CB view, CB country list, and CB/province selector without relying on which picker route was used. Static validation passed; runtime behavior still needs a game test.

Subject targets: spy start, the 20-network threshold, and recall use top_overlord_or_this. The CB job, type, eligibility, and province selection remain attached to the chosen target. Existing jobs refresh their endpoint mapping when missing or when overlord changes. Runtime verification required.
