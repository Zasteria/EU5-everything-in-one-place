# Окно — весь чек-лист разом

**Читать до того, как тронуть любой `.gui`.** Каждая строка ниже стоила прогона,
некоторые — трёх. Владелец, 2026-09-06: «меня заебало решать проблему окон чуть
ли не через одну сессию». Проверки, помеченные ✔, стоят в
`tools/check_script.py` и падают на сборке; всё остальное молчит.

## Форма окна. Не выдумывать — эта скопирована с `ai_settings_menu.gui`

```
window = {
	name = "bag_wtp_x_window"          # ✔ должен быть в gui/scripted_widgets/
	datacontext = "[GetPlayer]"
	allow_outside = yes
	alwaystransparent = no
	parentanchor = center
	widgetanchor = center
	movable = yes
	size = { W H }
	using = bg_window_default_alt      # ✔ рамка. Только здесь и больше нигде
	visible = "[...IsSet]"
	enabled = "[...IsSet]"

	widget = { ...крестик... }         # parentanchor = right, торчит наружу нарочно

	vbox = {
		using = window_margin_alt
		window_header_alt = { ... }
		vbox = { layoutpolicy_horizontal = expanding ... }   # всё содержимое
	}
}
```

**Между `window` и внешним `vbox` не бывает ничего.** Лишний `widget` со своим
размером держит свою ширину, и шапка внутри него не тянется за окном. Это
чинилось трижды свойствами самой шапки и не чинилось; **тип `window_header_alt`
не объявлен нигде в `reference/`**, читать его ширину отсюда нечем. Ответ пришёл
из окна игры той же формы. **Когда тип не читается — читается окно игры, которое
им пользуется.**

## Пять правил, которые молчат

1. **✔ Окна, которого нет в `gui/scripted_widgets/*.txt`, не существует.** Файл
   разбирается, типы регистрируются, ошибок нет — и виджет не создаётся никогда.
   Симптом худший в этом репозитории: всё работает и ничего не происходит.
   Строка `gui/<file>.gui = <name>`, и имя должно совпадать с `name` окна.
2. **✔ Рамку рисует одна строка, и её отсутствие молчит.**
   `using = bg_window_default_alt` — это граница, подложка шапки и лист разом.
   Без неё окно открывается, работает и не имеет краёв. Три окна потеряли её
   разом, когда скрипт перенёс её «на первую строку `size = {`»: в четырёх файлах
   из пяти типы объявлены **выше** `window`, и строка попала внутрь типа.
3. **✔ Ряд не шире, чем `W − 40`.** «Шапка не растягивается» — это **не** шапка:
   рамка, фон и крестик остаются при объявленном размере, а всё остальное
   `allow_outside` выпускает наружу. Мерить, а не смотреть: у окна редактора было
   объявлено 1500 при ряде 1544. **Запас вычитается из коробки, а не
   прибавляется к ней** — проверка, повёрнутая не в ту сторону, пропускала это
   шесть сборок подряд.
4. **✔ Каждое имя, которое окно называет, должно разрешаться**: ключ локализации,
   `Custom()`, `GetScriptedGui()`, список датамодели, `ScriptValue()`. И русский
   рядом с английским — он играет по-русски.
5. **Коробка с запасом места делит его между детьми.** Не «прижимает к краю», а
   раздаёт разницу поровну. Лечится растягивающейся пустышкой последним ребёнком
   — и **только не в коробке, на которой висит `datamodel`**: статический ребёнок
   рядом с датамоделью — это форма, которая роняла игру четыре сборки подряд.

## Что нельзя, и что вместо

| нельзя | почему | вместо |
| --- | --- | --- |
| `flowcontainer` + `datamodel` | роняет игру молча | `hbox`/`vbox`, ряды выписаны |
| `fixedgridbox` для сетки ячеек | рисует ячейки друг на друге | ряд — это `hbox` |
| размер на `hbox` | не держится: дети схлопнулись — коробка схлопнулась | `widget` с размером, `hbox` внутри |
| якорь на прямом ребёнке `hbox`/`vbox` | отказ, 124 строки в `error.log` | обернуть в `widget` |
| ячейка под номер сущности | невидимая держит своё место, ряд с дырами | ячейка под **место**, диспетчер внутрь |
| два разных смысла в одном столбце | разъезжаются оба | по столбцу на каждый |
| статический ребёнок в коробке с `datamodel` | та же форма, что роняла игру | вынести наружу |

## Мелочи, каждая из которых стоила круга

- **`layoutpolicy = expanding` на ребёнке коробки, у которой есть свой размер**,
  даёт ноль ширины и `elide` в пустоту — читается как непечатающаяся переменная.
  Виджет, у которого есть **и** политика, **и** свой размер, — другое дело.
- **`hbox` подгоняется под детей**, поэтому всё после датамодели едет вместе с
  ней. Фиксированные позиции держит только простой `widget`.
- **Скрытый ребёнок держит своё место**, пока на коробке нет `ignoreinvisible`.
  А `hbox`, у которого невидимы **все** дети, сам остаётся видимым и держит свою
  высоту — гасить надо сам ряд.
- **`visible` не умеет спросить триггер.** Оно читает переменные и функции
  данных, и только их, поэтому условие ячейки считается заранее эффектом и
  кладётся флагом: `where_to_produce` так гасит клетку недоступной грамоты
  (`_right_ok<n>`) и так же запоминает выбранный товар (`bag_wtp_good_index`) --
  номер, а не скоуп, потому что скоуп строки датамодели до нумерованной глобалки
  не достаёт.
- **Условие внутри значения ключа локализации ломает клетку.** `SelectLocalization`
  с вложенным сравнением прямо в значении — форма из игры, и в клетке сводки
  `where_to_produce` она сломала столбец целиком (2026-09-09). Работает другое:
  два готовых ключа без условий и `customizable_localization`, который между ними
  выбирает.
- **`And(...)` в выражении GUI вычисляет обе стороны**, а не ленится.
- **Значок-текст берёт размер шрифта, `icon` — долю ряда.**
- **`text_multi` с `autoresize` и без `maximumsize` не переносит, а растёт.**
- **`GetLocations` отдаёт озёра, моря и непроходимое** — фильтровать.
- **`block` внутри `blockoverride` до экземпляра не доходит.**
- **`§Y…§!` печатается буквально**; разметка игры — `#Y …#!`.
- **Скин ставится на виджет, а не в блок `background`.**

## Правило про правку пяти файлов сразу

Скрипт, который правит несколько `.gui` по позиции, **ищет якорь внутри нужного
блока, а не первый подходящий в файле**. Трижды за одну сессию массовая замена
попадала не туда: `using` рамки — внутрь типа, отступы — в чужой ряд. Дешевле
найти `window = {` и идти от него.

## Окно берёт скоуп один раз, на контейнере содержимого

Окно замены открылось пустым: оба `datamodel` читали локацию со скоупа, который
несла кнопка открытия, а кнопка его больше не несла. **Локация берётся один раз
на `vbox` содержимого** — `datacontext = "[GetGlobalVariable('..._swap_loc').GetLocation]"`
— и списки идут от неё: `Location.MakeScope.GetList(...)`. Прогон 09-13.

**И счётчик в заголовке рядом со списком**: `[GetDataModelSize(...)|W]`. Пустой
список и потерянный скоуп выглядят одинаково — ноль отличает их за один взгляд.
**Он же и доказал, что дело не в данных**: на следующем прогоне числа стояли
верные (3 и 23), а рядов не было.

## Ряд датамодели: две ошибки, от которых он не рисуется при верных числах

Обе — в списке ниже, обе окно замены совершило сразу, и вместе они дают пустой
список при непустой датамодели. Прогон 09-14.

1. **Тип ряда был `hbox` с размером.** Размер на `hbox` не держится: он
   подгоняется под детей. Тип ряда — `widget` с размером, `hbox` внутри.
2. **`datamodel` висел на коробке, которую подставляет `scrollbox_content`, и у
   `scrollbox` был свой размер.** `layoutpolicy = expanding` у ребёнка коробки
   со своим размером даёт нулевую ширину. Проверенная форма — та, которой окно
   плана рисует свои ряды: `widget` с размером снаружи, `scrollbox` тянется
   политикой, `datamodel` — на **вложенной** коробке.

## `visible` не умеет спрашивать триггер — только переменную

Сводка городских прав показывала Вюртембергу грамоты Константинополя: строка
рисовалась на каждое право в игре. Что стране доступно, знает триггер, а
`visible` читает только переменную, поэтому доступность раскладывается по
глобалкам заранее (`_right_ok<k>`, их пишет `_refresh_rights`), и строка
спрашивает `.IsSet`. Прогон 09-13.

## Датамодель в `scrollbox` читает глобальный список, а не унаследованный скоуп

Третий заход на одно и то же пустое окно. Число в заголовке печаталось верно
(4 и 24) — оно стоит в той же коробке, что и `datacontext`. `datamodel` стоит
глубже, **внутри `blockoverride` у `scrollbox`**, и что `datacontext` туда
доходит, в этом дереве ничем не доказано: единственная работающая датамодель в
`scrollbox` — строки плана — читает `GetGlobalList(...)` и в скоупе не
нуждается. Лечится тем же: эффект зеркалит список в глобальный, окно читает
глобальный. Прогоны 09-13 и 09-14.

## Список настроек CMF не рисуется без своего `_on_changed`

CMM показывает строку списка только пока показан
`GetScriptedGui('<mod>__<setting>_on_changed')`, а регистрация списка — это то,
что помечает настройку как имеющую такой GUI. Без него виджет скрыт целиком.
**Но группа рисуется**: список лежит в группе, названной по нему же, — и на
экране это читается как пустой список, а не как пропавший. Два прогона; ловит
`check_script.py`.
