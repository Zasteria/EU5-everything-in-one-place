# Резервация по стеснённости: построена, измерена, снята

**Снята 2026-09-07 в тот же день, что и построена.** Правило отработало в полную
силу и не сдвинуло ничего, а прогон, который должен был его проверить, вместо
этого закрыл сам вопрос: **план уже ровен, и `stone` уже стоит на уровне** —
45 домиков плюс 15 своих РГО равно 60 против 61 у `beer`. Числа целиком —
[`TESTLOG.md`](../../TESTLOG.md), 2026-09-07; строка ответа — [`SETTLED.md`](../../SETTLED.md).

**Чего этот документ стоит теперь.** Ниже — правило и его устройство, как они
были построены: если резервация когда-нибудь понадобится на другой земле,
восстанавливать её не надо выводить заново, это один коммит. И ниже же —
ошибка, из которой она выросла, потому что она дороже самой резервации:
**в таблице считались неиспользованные сельские комнаты вместо достигнутого
уровня.** `stone` «недобрал 19 мест» — и не хотел их: его квота кончилась.
**Мера равномерности — это `n + rgo` против квоты, а не занятые комнаты.**

## Что она чинит, числами последнего прогона

Северная Германия, 416 локаций, 132 города, 284 села; уровень, на который выходят
все, — **61** домик считая РГО. Товары, чей потолок на своей стороне **ниже**
этого уровня, — единственные, кого резервация может тронуть:

| товар | сельских мест | взял | недобрал |
| --- | --- | --- | --- |
| `iron` | 28 | **28** | 0 — взял всё |
| `stone` | 53 | 34 | **19** |
| `salt` | 42 | 31 | **11** |
| `fish` | 42 | 18 | 24 — но 21 из них взяли судовые припасы |
| `naval_supplies` | 42 | 21 | 21 — то же самое с другой стороны |

**Чистые случаи — `stone` и `salt`.** Их сельские здания (`stone_quarry`,
`salt_collector`) не нужны никому другому, то есть за само здание конкуренции нет
— они потеряли **тридцать комнат** тем, у кого в сёлах по 284 альтернативы.
`fish` и `naval_supplies` делят рыбацкую деревню и заняли 39 прибрежных локаций
из 42: там резервация не даст ничего, она лишь переложит места между ними.

**Значит ожидаемая цена — около тридцати комнат**, снятых с товаров, стоящих на
61, то есть по одному-двум с каждого.

## Правило

> **У локации есть хозяин: самый стеснённый из товаров, которые вообще могут
> встать на этой её стороне.** На ступенчатых кругах локация предлагается только
> хозяину (и тем, кто с ним вровень); на общих кругах она открыта всем.

Стеснённость — это `_ngt<n>` / `_ngr<n>`, число локаций выбранной земли, где
товар может встать на этой стороне. Числа уже считаются `_plan_score`.

**Почему «только на ступенчатых кругах» — и это главное в правиле.** Освобождать
локацию, когда хозяин закончил, дорого: пришлось бы на каждую локацию спрашивать,
хочет ли хозяин ещё. А отпускать её на общих кругах того же круга — бесплатно и
даёт тот же результат: хозяин выбирает первым в каждом круге, остальные получают
остаток в том же круге. Никакого состояния заводить не нужно.

## Как построено

**1. Хозяин — одно число на локацию на сторону, считается один раз.** После
`_plan_score` (там `_ngt`/`_ngr` уже окончательны) один обход по `_candidates`:

```
if = {                                     # городская сторона; else — сельская
    limit = { _plan_is_town = yes }
    set_variable = { name = _ownt value = 99999 }
    <на каждый товар n, умеющий в город>
      if = { limit = { var:_pm<n> > 0  var:_ownt > global_var:_ngt<n> }
             set_variable = { name = _ownt value = global_var:_ngt<n> } }
    <второй проход, только ради отчёта>
      if = { limit = { var:_pm<n> > 0  var:_ownt = global_var:_ngt<n> }
             change_global_variable = { name = _owt<n> add = 1 } }
}
```

**`var:` слева, `global_var:` справа** — эта форма в моде доказана, обратная нет,
а сравнение, которое молча читается ложью, отдало бы землю не тому.

**`_pm<n>` / `_prm<n>`, а не `_plan_can_*`.** Хозяин — свойство земли, а не того,
что на ней уже стоит; `_plan_can_*` спрашивает свободную комнату и менялся бы по
ходу раздачи. 416 × 47 сравнений один раз — ничто рядом с самой раздачей.

**2. Ворота в `_plan_pick_<n>`**, внутри `limit` обхода, по одной строке на
сторону:

```
OR = {
    global_var:_plan_tier = 0
    var:_own<sfx> = global_var:_ng<sfx><n>
}
```

`_own` — минимум, поэтому `_ng<sfx><n> >= _own` всегда, и равенство означает
ровно «я один из самых стеснённых здесь». `var:x = global_var:y` в моде доказано
(`var:_rtry >= global_var:_rband`).

**3. Обнуление** — там же, где `_load` и `_plan_prank`: в обходе `_plan_prepare`
и в `_ext_prepare`.

**4. И четвёртое место, которого в проекте не было.** `_px<sfx><n>` — «этому
товару места кончились» — ставился перед обходом на **всякой** полосе 0, и
снимал его сам обход, если что-то нашёл. Это было верно, пока обход на полосе 0
ничего не отсекал. Резервация отсекает: товар, не владеющий ни одной свободной
локацией, не найдёт ничего на круге `band0/tier1` — а снять флаг после этого уже
некому, и товар выпал бы из плана до конца, молча. Флаг ставится теперь только
на **общем** круге полосы 0. **«Не нашёл» перестаёт значить «нет», как только
рядом появляется фильтр** — и это единственное, что новое правило сломало бы
незаметно.

**Хозяева считаются в хвосте `_plan_score`**, а не отдельным вызовом из
`_plan_run` и из «Расширить»: к концу `_plan_score` числа `_ng` окончательны на
обоих путях, а два вызова — это два места, которые расходятся молча. Доливка
поэтому и считает хозяев заново, хотя её раздача ходит только по новой земле.

**И только своя сторона у каждой локации**: `_plan_can_town_<n>` требует
`_plan_is_town = yes`, `_plan_can_rural_<n>` — `no`, так что городскую локацию
никто никогда не спросит про `_ownr`, и считать его там незачем.

**Больше ничего.** Ни флага «хозяин закончил», ни списка, ни второй памяти.

## Чем проверять — предсказание, по которому правило либо живёт, либо снимается

Прогон на той же северной Германии, «Пересчитать», «Диагностика». Ждём:

- **`stone` 45 → около 60**, `salt` 36 → около 47 (в сводке — столбцы «Домиков» и
  «Мест»);
- **товары на 61 опустятся на 1–2** — это и есть заплаченная цена;
- **`fish` и `naval_supplies` не сдвинутся** (они вровень, 42 и 42);
- **`iron` не сдвинется** — он и так взял все свои 28.

**И `owt`/`owr` — чем «не сработало» отличается от «сработало и ничего не
изменило».** Это новые числа на строке товара в «Диагностике»: сколько локаций
товар держит как самый стеснённый. `tools/diag.py` печатает их одной строкой в
«коротко», и они читаются так:

- `stone` и `salt` с `owr` около нуля — правило их не защитило, хозяином всюду
  оказался кто-то ещё, и снимать надо **правило**;
- `owr` в десятках, а сводка не сдвинулась — правило сработало, а связало товар
  что-то другое (квота своей стороны, уровень, потолок села), и искать надо
  **это**, не переписывая резервацию.

**Если не сдвинулось ничего и хозяев ни у кого нет — правило снять**, как сняли
ступень по сторонам: она была верна по смыслу и дала ноль на этой земле.
