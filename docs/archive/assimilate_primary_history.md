# `assimilate_primary` до 0.5.0 — история

Вынесено из `mods/assimilate_primary/CLAUDE.md` 2026-10-12, когда мод стал
своей автоматикой совета.

0.4.0 (10-12): ежемесячное включение `cabinetactions` убрано; галочка
`cabinetactions` с записью «до/после» в `debug.log` — теперь в группе
«Отладка». Технические вещи — в CMF, не в игровые окна (его слова 12.10).
0.3.0 (10-05) включал `cabinetactions` раз в месяц; в игре так и не был.

**«Ассимиляция провинции» на автоматике совета целит в основную культуру;
в признанную — только там, где признанная уже ведёт в провинции на 30
процентных пунктов** (его правило 10-05). Механизм ванили и откуда он —
[`docs/research/vanilla.md`](../../docs/research/vanilla.md).

Файл — копия `cabinet_actions/promote_culture.txt` игры целиком (подменяет её
по имени, как QoL подменяет `stabilize_country.txt`). Собирает
`tools/generate.py`, `refresh.py` его гоняет; если игра вернёт свой штраф
«Wrong culture», генератор остановится. Порог — `LEAD` в генераторе.

**0.1.0** — штраф −1000 в конце `ai_will_do`. Прогон 10-05: ни один советник
ни разу не взял ассимиляцию (лог чистый, мод смонтирован). Почему — не
измерено: отрицательная оценка могла топить всё действие целиком.

**0.2.0** — оценку не трогает. Правило стоит в `enabled` выбора провинции, где
игра сама сужает выбор ИИ, и действует только при
`is_system_automated = cabinetactions` или `cabinet` (имена по шаблону
`credit`/`buildings`; неверное имя дало бы ошибку загрузки). Вручную, без
автоматики, можно выбрать что угодно.

**0.2.1** (его просьба 10-05: боты не должны тупить из-за мода) — правило ещё
и под `is_ai = no`: компьютерные страны идут по ванили целиком. 0.1.0 штрафовал
всех, ботов тоже.

**Не проверено (всё):** что делает `cabinetactions` и читается ли «after» в том же тике; берёт ли автоматика ассимиляцию в основную вообще;
верны ли имена систем; если и 0.2.0 молчит — смотреть, чем заняты советники
и какую оценку `ai_will_do` даёт основная культура против других действий.

## 0.5.0 → 0.6.0 (10-12)

0.5.0 в его прогоне 10-12 не сделал ничего (`docs/TESTLOG.md`): трогал только
пустые места, а он нарочно занял все; месячного шага в логе не видно (висел на
`monthly_country_pulse` и о себе не писал). Он ждёт, что автоматика **владеет
всеми местами** — отсюда раздача 0.6.0. `cabinetactions` — не система
автоматики вовсе (`Failed to read enum! Type: EAutomatedSystems`), галочка
отладки и это слово в правиле игровой автоматики убраны.

## 0.7.0 (10-12)

Его просьбы после 0.6.0: имена строк — ссылка игры
`[ShowCabinetActionName('<действие>')]` (как здания CM), вкладка «Тонкие
настройки» (пока список без настроек), номер места (`cmf_dev_beta` +beta8),
порядок интеграции.

## 0.8.4–0.8.5 (10-12): экстренное восстановление и правило интеграции

Вынесено из брифинга при 0.9.0. Восстановление сработало в игре на паузе (TESTLOG, 10-12 22:45).

- **Экстренное восстановление** (0.8.4): ребёнок плашки «разорённые районы»
  (`bag_alert_banner.gui`, `tools/alert_banner.py`; `quiet_alerts` снят 10-12;
  узнаёт по `GetTitleKey`) при включённой автоматике — при появлении и раз в
  1 с — зовёт `bag_asp_emergency`: каждой провинции с районом < 0 без
  восстановления — пустое место или самое низкое действие **ниже
  восстановления** (его правка 10-12). Зонд: `the devastated locations alert
  is showing`. Не по жёлтому цвету: жёлтые висят всегда (его слово 10-12).
- **Интеграция** (его правило 12.10, не настройка): сначала провинция, где
  больше завоёванных районов с основной культурой ≥ 50 % (интегрируются вдвое
  быстрее), потом — с признанной ≥ 50 %, потом по населению (`INTEGRATION`).

## Раздача мест, как устроена (вынесено при 0.9.0)

- **Раздача** (`bag_asp_plan`): сверху вниз по «Приоритету» каждое отмеченное
  действие сначала оставляет за собой места, где оно уже идёт, потом берёт
  свободные — советника с лучшим навыком этого действия (`ordered_cabinet`,
  `order_by = cabinet_member.<adm|dip|mil>`), пока есть цель и свободное место.
  Действие с `allow_multiple` может взять несколько мест. Занятое место
  снимается (`stop_cabinet_action`) перед новым. Что осталось никому не нужным,
  сохраняет своё (в т. ч. действия вне котла).
- Раз в `review` мес. (0 — никогда) — полная раздача; иначе раз в `period` мес.
  — только места без действия.
- Цель проверяется **копией `visible` и `enabled` самого действия** из его
  `select_trigger`; триггеры «другое место уже делает это» сравнивают с `root`,
  у нас это страна — генератор заменяет их переменной `bag_asp_busy_<действие>`
  на занятых целях (ставится и снимается за проход).

## 0.9.0–0.9.1 (10-12…13), вынесено при 0.9.3

- **0.9.0–0.9.1, его список 12.10 и правка 13.10**: `POOL` дописан в конец
  (CMF держит строки по номеру): Noblesse Oblige (видна по `is_visible_for`) и
  дипусилия «неприязнь» (`ROW_ACTION`; только при
  `has_countries_with_(near_)coalition_grade_antagonism`). «Тонкие настройки» —
  только группы CMF (список строк убран, его слово 13.10): цель ассимиляции
  (основная / признанная), цель обращения (государственная / другая той же
  группы), «Ускорять контролем». **Ускорение (0.9.1)**: за каждой ассимиляцией
  сразу её место контроля (`bag_asp_pair`: Noblesse Oblige, иначе повышение
  контроля), привязано к ней (`bag_asp_paired` у советника), в «Экстренном»
  считается её рангом, снимается вместе с ней (`bag_asp_unpair`).

## Пересчёт (0.9.3) и 0.9.0–0.9.1, перенесено из брифинга 10-13

- **Пересчёт (0.9.3, его правило 13.10)**: полная раздача по умолчанию
  каждый месяц (`review` = 1), сразу при смене списков (`_on_changed`) и при
  новом советнике (`on_cabinet_assigned`, лист сливается с игровым). В полной
  раздаче строка переносит своё действие с целями к лучшему по навыку
  свободному советнику (`bag_asp_move_<row>`); сохраняет ли игра прогресс при
  переносе — не мерено.
- **0.9.0–0.9.1**: Noblesse Oblige, дипусилия «неприязнь», «Тонкие настройки» —
  группы CMF; ускорение контролем (`bag_asp_pair`) — подробно в архиве.
