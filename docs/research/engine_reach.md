# Скриптовый API — не граница мода

**Это писано по его требованию, 2026-09-17, дословно: «ты заебал мне постоянно
упираться в других вещах, что ты не можешь».** Повод был ровно такой: сессия
посмотрела в `effects.log`, не нашла эффекта на ползунки экономики и объявила
задачу невыполнимой. Через два захода мод двигал эти ползунки.

**«Нельзя» произносится последним, а не первым.** Пустой `effects.log` — это
факт про скриптовый API. Про игру он не говорит ничего.

## Лестница. Спрашивать сверху вниз, и только пройдя её целиком — говорить «нет»

**1. Скриптовый эффект.** `python3 tools/api.py <имя>`. Дёшево, надёжно, и это
единственная ступень, которую сессии обычно проходят.

**2. Функция интерфейса, которую можно позвать из своего виджета.** Всё, что
игра делает по нажатию кнопки, делается функцией, и эта функция зовётся из
`onclick` или `on_start` **нашего** скрытого виджета. Проверено прогонами:
`ToggleAutoMinting` переключает ванильную галочку автоматики (09-16),
`BuildOrExpandBuildingDefault(BuildingType, Location)` действительно строит
здания (09-14). Искать: `python3 tools/api.py --find <слово>`.

**3. Свой виджет, привязанный к объекту движка, — он не только читает, но и
пишет.** Самое сильное, и самое неочевидное. Если у игры нет функции-сеттера,
но есть **виджет**, которым игрок это меняет, — мод заводит такой же виджет,
привязывает его к тому же объекту и подставляет ему своё число. Так двигаются
ползунки «Чеканка» и «Содержание», у которых нет ни эффекта, ни функции с
аргументом: форма целиком — в
[`interface.md`](interface.md#привод-к-ванильному-ползунку-форма-которая-работает).

**4. `ExecuteConsoleCommand('...')`.** Консоль игры зовётся из виджета как
обычная функция, и команда `effect <любой скриптовый эффект>` делает из неё
мост «интерфейс → скрипт» без `scripted_gui`. Так CMF отправляет текстовые
настройки. CMF прячет такое за галочку «unrestricted tools» — то есть считает
читерством, а не недоступным.

**5. Мост в обе стороны.** Скрипт → интерфейс: переменная страны, читается
`[FixedPointToFloat(GetPlayer.MakeScope.GetVariable('x').GetValue)]`. Интерфейс
→ скрипт: `GetScriptedGui('x').Execute(GuiScope.SetRoot(GetPlayer.MakeScope).End)`.
Число через `AddScope` не передать — скоуп это объект; передаётся переменной.

**6. Такт без игрока.** `state = { trigger_when = "[...]" on_start = "[...]" }`
срабатывает, когда выражение стало истинным; `state = { duration = 0.1 next = ... }`
даёт цепочку и, замкнутая, — постоянный такт. Виджету не нужен ни игрок, ни
открытая панель.

**И обратная сторона: числа движка читает скрипт.** Триггер страны работает
как значение — `set_variable = { name = x value = stability }` — форма самой
ваниллы. Так `war_sliders` снимает положение ползунка чеканки
(`slider_minting_value`) и инфляцию, чтобы считать по ним.

## Что на этой лестнице молчит

- **Глобальный promote годится только для выражений данных.** В колбэке
  (`onclick`, `onvaluechanged`) и в `datamodel` он не берётся: кнопка остаётся
  вообще без обработчика, список — пустым. На экране это «ничего не
  происходит», в `gui.log` — «failed reading callback, at <файл>:<строка>» и
  «Property 'datamodel'(1002) not handled». Скоуп берётся `datacontext`-ом.
- **Событие рождает смена значения, а не его наличие.** Виджет, показанный уже
  на нужном числе, молчит. Привод взводится одним числом, настоящее приходит
  вторым шагом.
- **Скрытый виджет не пишет** — на этом держится «мод просыпается и засыпает».
- **Объекты панелей резолвятся не везде.** `GetEconomyView` — глобальный
  promote и отдаётся даже с закрытой панелью (топбар держит его в тултипе
  золота), а `LocationProductionView` из чужого виджета не резолвится вовсе.
  Проверять, а не предполагать.
- **`error.log` и `gui.log` называют файл и строку** и для непривязанного
  колбэка, и для отвергнутого свойства. Эффект, который просто ничего не
  делает, не логирует ничего — поэтому у привода должен быть счётчик
  сработавших, иначе «скрипт сделал, интерфейс не дошёл» неотличимо от «не
  срабатывало вовсе».

## Чего на ней действительно нет

Чтобы следующая сессия не искала заново:

- **числа в аргументе `scripted_gui`** — только через переменную;
- **закрыть боковую панель из чужого виджета** — `LateralView.Close` есть, но
  глобального способа достать эту панель в дереве не нашлось;
- **нажать чужую кнопку или сдвинуть чужой ползунок** — «+»/«−» сидят внутри
  движкового `ranged_slider`, функции под ними нет. Поэтому и заводится свой
  виджет.
