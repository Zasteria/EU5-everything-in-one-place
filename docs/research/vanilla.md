# Ванильное поведение: разборы по файлам игры

Как игра решает то, что игрок видит, но не выбирает сам. Каждая запись: что он
наблюдал, механизм с файлом и строкой, что из этого доказано файлами, а что
выведено.

## Автоматика совета ассимилирует в признанную культуру, а не в основную (бета 1.4)

**Наблюдение (05.10, Румыния, основная валашская, молдавская признанная).**
Советник на автоматике ставит «Ассимиляцию провинции» Торда в молдавскую
(3,35 % провинции), хотя валашской там 15,28 %; переназначение не держится,
автоматика возвращает молдавскую.

**Механизм** — `in_game/common/cabinet_actions/promote_culture.txt`:

- Выбор культуры: `enabled = { is_primary_or_accepted_in = scope:actor }` —
  основная и признанные на равных.
- `ai_will_do` — база от статуса преобладающей культуры провинции (6/4/2 минус
  её мнение о культуре страны), от целевой культуры не зависит; затем
  `multiply = 1 - culture_percentage(target)`. Чем **меньше** целевой культуры в
  провинции, тем выше оценка. Торда: молдавская 0,966, валашская 0,847 —
  молдавская выигрывает всегда, пока её меньше.
- В 1.3 (`d882840b`) ИИ видел только основную (`is_primary_in`), и стоял штраф
  `-1000 "Wrong culture"` за цель не в основную. Патч 01.10 (`94932966`) открыл
  признанные и **штраф убрал**. В `assimilate_area.txt` тот же штраф оставлен —
  в области автоматика целит только в основную.
- Для ИИ провинция ещё должна пройти `naturally_assimilating_culture = target`
  хотя бы в одном районе; как движок выбирает эту культуру, в скрипте не видно.
  Валашская и молдавская устроены одинаково (`cultures/carpathian.txt`: один
  язык, одни группы, взаимно kindred).

**Не доказано:** что автоматика кабинета игрока считает именно `ai_will_do`
(выведено: другого источника оценки в файле нет).

**Правка:** мод [`assimilate_primary`](../../mods/assimilate_primary/CLAUDE.md).
0.1.0 вернул штраф −1000 — и советники перестали ассимилировать вовсе (10-05,
причина не измерена). 0.2.0 убирает признанную из `enabled` провинции при
автоматике, кроме провинций, где она ведёт на 30 п. п.

**Автоматика совета — два переключателя** (`automation_lateralview.gui`, так же в
1.3): «Члены совета» (`cabinetmembers`, нанимает на места) и «Совет» (`cabinet`,
выбирает действия). **Третьего нет:** `cabinetactions` — не значение `EAutomatedSystems` («Failed to read enum!», его прогон 10-12), так что зонд +perf28 «выключен» 10-05 читал сломанный триггер, а не переключатель; строка локализации есть, системы нет. `AI_PERFORMANCE_CABINET_ACTION_MONTHS_BETWEEN_UPDATES = 36`
в defines — срок смены заданий ИИ; **пустое место он не держит** (его 1 600 часов,
10-05: новое место всегда получает задание сразу).

QoL (Calidad de Vida 1.2.1) везёт `stabilize_country.txt` и `strengthen_government.txt` побайтово как в игре 1.4 (сверено 10-05): совет не меняет.

## Уведомления: «заглушить» уже есть в игре (бета 1.4, 10-06)

`alertmanager.gui:466–481`: правый клик по уведомлению — `AlertEntry.Hide` (в
корзину справа, **вернётся при изменении содержания**); **Shift + правый клик —
«Скрыть и заглушить»** (`Hide` + `SetMuted`): `ALERT_MUTED_TT` «не появится на
панели, даже если его содержание изменится». В меню уведомлений
(`alert_settings.gui`) у каждого — переключатель «Заглушить» и «Сбросить»
(`SetDiscarded`, пропадает и из корзины). Ни Río, ни наши моды эти файлы не
заменяют. Не проверено: переживает ли заглушка сохранение. Hide Annoying
Alerts (3605651135, игра 1.0) заменяет `alertmanager.gui` целиком файлом 1.0
(старый API `AlertItem`, 5.5 тыс. строк против 8 тыс.) — на 1.4 не ставить; из reference убран 10-06 по его просьбе. Мод со списком «не показывать» повторил бы ванильное «Заглушить»: запись `AlertEntry` одна на вид уведомления (эпидемия — одна на все болезни, `has_disease`) и, судя по меню, держит заглушку и неактивной.

## Замок на месте в совете (1.4, из файлов, в игре не мерено)

Замок — на **месте** (`Cabinet`), не на персонаже: кнопка в
`government_lateralview.gui:4435`, `CabinetItem.ToggleLockedStatus`.
Подсказка (`LOCK_CABINET_DESC`): «Запретить менять это место в совете при
автоматизации». Значит, держит место от обеих автоматик панели («Члены совета»
и «Совет»); раздельно ли — не видно.

**Скрипту замок не виден:** `Cabinet.IsLocked` есть только как функция
интерфейса, триггера нет (`api.py --find lock`). Прочесть его можно только из
окна; дешёвый путь — второй `onclick` на той же кнопке замка, пишущий
переменную через scripted gui (`Cabinet.MakeScope` есть). Снимает только
щелчки после установки мода.

`Cabinet.GetAIDebugTooltip` есть в дампе, ваниль его нигде не рисует —
возможно, разбор оценки автоматики по месту. Подсказка рисуется только при
наведении.

## Сдвиг ценностей советником (1.4, из файлов, в игре не мерено)

`change_societal_values` — действие движка: в файле только `ability = dip`,
`societal_values = 0.1`, `forbid_for_automation = yes`, без `select_trigger`.
Пару и сторону выбирает окно `select_societal_value.gui`
(`SocietalValueCandidate.SelectLeftCandidate` / `SelectRightCandidate`).
**`set_cabinet_action = { type = cabinet_action:change_societal_values target =
societal_value_type:… }` ставит действие с пустой парой** (его прогон 10-12:
«Изменение общественных ценностей «» на в пользу «NAME»»); другого параметра в
дампах нет. Окно выбора открывает `ChangeCabinetActionTarget(Cabinet)` (правый
щелчок, `map_markers.gui`), `Scope.GetCabinet` даёт `Cabinet` из скриптовой цели; скрипт видит
`societal_value_cabinet_action` (у действия есть ценность) и
`societal_value_progress`, интерфейс — `Cabinet.GetSocietalValue`,
`GetMaxSocietalValueReachable`, `HasReachedMaxSocietalValue`. **Измерено 13.10:** переменная страны держит скоуп места (`set_variable = { … value = <cabinet> }`), и `GetVariable('x').GetCabinet.GetMaxSocietalValueReachable` читает его в локализации («сейчас -35.99, предел 49»). Подсказка игры: предел = 100 × месячный толчок в эту сторону. **Измерено 13.10 11:14 (`assimilate_primary` 0.9.9):** `ChangeCabinetActionTarget(<место на изменении ценностей>)` из скрытого окна открывает `select_societal_value`; строка, сравнившая `SocietalValueCandidate.GetSocietalValue.Self` с парой из переменной страны (`ObjectsEqual`), жмёт `SelectRightCandidate` сама; окно после этого остаётся открытым. **13.10 11:40:** окно не показывает пару, которую место уже двигает (12 строк вместо 13); `Cabinet.GetMaxSocietalValueReachable` даёт 0 у места не на этом действии и число у места на нём (dip 76: 12.79, затем 32.35 после тика). В скрипте левая сторона — минус (`pa_push_towards_traditionalist`: при `> 0` двигает влево). Сдвиг скриптом в
обход совета — `change_societal_value = { type = <пара> value = <±> }`.
