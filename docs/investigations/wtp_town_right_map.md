## Расчёт, ради которого это и брали

Всё считается **один раз за загрузку**, проходом
`bag_wtp_trmm_recompute_province_definition` по каждому определению провинции, и
кладётся переменными на каждый её кусок; карта и подсказка потом только читают.
Так у него, так и здесь: «Variables stored on the province_definition itself do
not read back, so everything is staged in locals and written to every slice».

**Единица покрытия — не процент, а бонус.** `bag_wtp_trmm_rgo_unit` (scope:
локация) = 0.1 базовых плюс по 0.025 за `rgo_logistics_discovery` и
`rgo_logistics_mil_choice`: столько «Местного доступа к сырью» даёт полностью
покрытая провинция. Всё остальное меряется в этих единицах.

**Вариант способа** `_opt_<товар>_<n>` (scope: определение провинции) — доля
**всего** входа этого способа, которую провинция может дать своим РГО:

```
bag_wtp_trmm_opt_wine_1 = {
    value = 0
    if = { limit = { any_location_in_province_definition = { raw_material ?= goods:fruit } }  add = 0.823 }
    if = { limit = { any_location_in_province_definition = { raw_material ?= goods:lumber } } add = 0.112 }
}
```

Числа — доли входа в рецепте. Заметь: **достаточно одной локации в провинции**,
дающей сырьё, чтобы доля засчиталась целиком.

**Покрытие товара** — лучший вариант, затем поправка на саму локацию:

```
bag_wtp_trmm_cov_wine = {
    value = 0
    if = { limit = { province = { has_variable = ... } } province = { add = var:... } }
    # право поднимает и само это сырьё, так что на его локации РГО входит
    # в среднее как ещё один полностью покрытый поставщик
    if = { limit = { raw_material ?= goods:wine } add = 1  divide = 2 }
    add = bag_wtp_trmm_lm_wine
}
```

`_lm_<товар>` — местный модификатор вывода этого товара, делённый на
`_rgo_unit`, **минус 0.2, если право уже выдано** (иначе карта хвалила бы землю
за то, что сама же на неё положила).

**Счёт права — среднее арифметическое покрытий его связки**, без весов:

```
bag_wtp_trmm_right_textile  = (cov_cloth + cov_fine_cloth + cov_dyes) / 3
bag_wtp_trmm_right_naval    = (cov_naval_supplies + cov_tar) / 2
bag_wtp_trmm_right_tooling  =  cov_tools
```

Дальше — лучший индекс `_best_idx` на локацию (им и красится земля), `_tie_idx`
для ничьих, `_tier_*` для «какое это место в списке» и `_rightval_*` — тот же
счёт, но в деньгах (`_val_<товар>` × доля бонуса права).

## Чем его счёт был лучше нашего, и что теперь считает план

Наш счёт прав считал **по локации**. У него — **по определению провинции**, и
это правильнее: грамота даёт «Местный доступ к сырью» всей провинции, а сырьё
лежит по разным её локациям. Три отличия, и все три были в его пользу:

1. **Вход считается долями рецепта, а не «есть/нет товара».** Товар, дающий 8 %
   входа, и товар, дающий 82 %, у нас весили одинаково.
2. **Способ выбирается лучший из возможных**, а не текущий.
3. **Собственное РГО локации входит в среднее как полное покрытие** — у нас оно
   не входило вовсе.

**Перенято 2026-09-14, и целиком.** Его слово: «Я хочу, чтобы выгода от земли
по городскому праву считалась тем же методом, что считается в этой карте.»
`bag_wtp_rq<k>` — единственное место, которым план и сводка меряют землю под
грамоту, — теперь среднее `_trmm_cov_<товар>` по связке, умноженное на
`RANK_SCALE`. На девяти общих грамотах это **ровно его число**.

**Считаем через `_cov_<товар>`, а не через его `_right_<право>`**: у него девять
грамот, у сборки тринадцать. Покрытий хватает на все, кроме `silk` —
константинопольская грамота считается по двум товарам из трёх, и это не ошибка,
а предел переноса.

**Старый счёт был денежный** — сумма `_p<n>` по товарам, которые город и правда
делает, делённая на всю связку. Он отвечал на «сколько принесёт», а спрошено
было «насколько земля подходит». `_plan_right_won_<k>` и `_plan_right_gate_<k>`
не тронуты: это факты и ворота державы, а не счёт.

## Как это запускается у нас

`bag_wtp_trmm_recompute_all` зовётся из `bag_wtp_register` за клеймом
`bag_wtp_trmm_stamp` (`bag_wtp_trmm_data_is_current`, версия
`bag_wtp_trmm_version_value`). **Клеймо здесь обязательно**: регистрация CMF
срабатывает при каждом открытии страницы мода, а не только на загрузке, — без
клейма это был бы полный проход по карте на каждое открытие.

Вручную — кнопка «Карта городских прав → Пересчитать» на «Технической»: сырьё и
модификаторы вывода по ходу партии меняются, а проход больше не идёт.

## Что поймал чекер на этом переносе

`set_local_variable` не считался записью, а `local_var:x` попадал в ветку
`var:(\w+)` шаблона чтения — перед `var:` там нет границы слова. Девятнадцать
честно записанных локалов были названы ошибкой. Исправлено в
`tools/check_script.py`.

## Тот же разбор в окне плана

Его слово, 2026-09-14: «если я наведусь в область строки с городским правом в
нашем окне плана — мне так же выпадала сводка какое право здесь наивыгоднейшее,
сколько % берут другие похуже и так почему».

Сделано его же второй копией. У него в кастомной локализации два набора слотов:
`_slot_*` читают локацию из корня окна (так устроена подсказка карты), а
`_ur_rank_slot_*` — из цели самой локализации, «so the build-location marker can
reuse the ranking tooltip where the window root is not the row's location».
Строка плана — ровно этот случай, поэтому `bag_wtp_plan_right_tt` дописан вторым
набором, и разбор в нём тот же, что на карте.

## Что из этого осталось в бриф не влезшим

**Двадцать режимов и полоса значков над баннером** — это весь перенос, и он
целиком в этом файле.

**`_rq<k>`, выгода земли под грамоту, — среднее нашего `_cov_<товар>` по
связке**, а не числа карты: карта берёт лучший способ безусловно, мы — лучший из
доступных по тумблеру эпохи. Потому «на сейчас» наши числа обязаны отличаться от
карты, а «на конец» — сойтись.

**Сама карта считается один раз, за клеймом `_trmm_stamp`** (регистрация CMF, а
она срабатывает и на каждое открытие страницы мода — без клейма это был бы полный
проход по карте каждый раз). Цвета выглядят старыми — «Пересчитать карту прав» на
«Технической».

## Вопрос, который он задал о самой формуле, 2026-09-14

**Знаменатель покрытия -- весь вход рецепта, включая то, что РГО не даёт вовсе.**
Его пример: судостроительные материалы на верхней ступени просят дерево 1.824,
прядильные 1.367, **дёготь 1.367 и текстиль 0.228** -- последние два производятся,
а не добываются. Сумма 4.786, из неё сырьём кормится 3.191, то есть **потолок
этого рецепта -- 66.7 %**, и провинция, у которой есть и дерево, и прядильные,
получает свои 66.7 % и выше подняться не может никогда.

Его вопрос: «если одна провинция даёт суд материал 66.7 % и одновременно
текстильной фабрике 100 % -- это ведь не значит, что эта провинция лучше для
текстильной фабрики. В моих глазах они становятся равны, ведь оба забирают
максимально возможный для себя бонус».

**Он прав в том, что это две разные шкалы.** Сейчас число отвечает на «какую долю
своего входа эта земля кормит сама» -- меру самодостаточности. Сравнивать по ней
**разные товары** нельзя: рецепт, собранный из одного сырья, обгоняет рецепт из
сырья и двух переделов просто по устройству, а не по тому, насколько земля ему
подходит.

**Потолок надо считать по локации, а не по товару.** По всему дереву почти у
каждого товара найдётся рецепт со стопроцентным сырьевым входом (часто у чужого
мода), так что общий потолок товара -- 100 % у девятнадцати из двадцати. Значение
имеет потолок **того рецепта, который здесь и правда может стоять**: в Зауэрланде
это `fishing_village/coastal_boatyard`, дерево 0.5 из 0.75, потолок 66.7 %.

**Правка -- одно число в генераторе**: доля ветки считается не от всего входа
(`amount / total`), а от его сырьевой части (`amount / raw_total`). Тогда рецепт,
чьё сырьё провинция даёт целиком, получает ровно 100 %, и товары сравнимы между
собой.

**Чем за это платят:** сотен становится много, и лесенка теряет часть
разрешения. Лечится тем, что абсолютная доля остаётся -- решает ничью и стоит в
разборе рядом, так что обе меры видны.

**Отложено его решением 2026-09-14, и это не «забыли».** «Пока не уверен.
Оставим этот вопрос пока. Сначала я поиграю с таким вариантом, потом может с
другим и посмотрю что лучше ощущается.» То есть сравнивать он собирается **на
ощупь, в партии**, а не по коду, и первый вариант — нынешний, абсолютный.

**Значит: не поднимать это самому.** Придёт с ответом — правка одна строка
(`amount / total` → `amount / raw_total`), и к ней сразу вторая половина:
абсолютная доля остаётся решать ничью и стоять в разборе рядом, иначе лесенка
теряет разрешение на множестве сотен.
