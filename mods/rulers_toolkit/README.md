## Командиры из правителей

- **Мир:** раз в месяц до 20 шагов; шаг — первый в очереди свободный правитель
  (`crown_estate`, «Правители»; правитель первым, потом сумма навыков
  `total_abilities` — 0.2.0, его просьба; не в совете, ничем
  не командует, `is_eligible_military_leader`) встаёт на самый большой отряд без
  правителя. **Ветвь — где отрядов меньше** (`bag_rtk_navy_pays_more`, счётчики
  `bag_rtk_n_army`/`_n_navy`; поровну — армия): власть от командования армиями и
  флотами — два котла по 25 % (`BASE_ESTATE_POWER_FROM_COMMAND`), каждый делится
  между командирами ветви (его слова; делится поровну или по размеру — не мерено).
  Отряд с любым правителем (наследник, поставленный руками, тоже) не трогаем;
  советников (`in_cabinet`) не берём — смена совета стоит валюты. Чисто наёмный, изгнанный, в бою — мимо.
  Флоты — галочка `cmd_fleets`, по умолчанию вкл. (новый id: в старом сейве
  `cmd_navy` стоял выкл.).
- **Война:** при «Генерал-правитель» правитель без отряда — на самую большую армию.
- **Зонд:** `bag_rtk: month, peace pass` (настройка включена, мир),
  `bag_rtk: crown commander set` на каждое назначение.

## Творения

`bag_rtk_art.txt`: 1-го числа, пока дипломатов ≥ «оставлять» + 1 (они дробные),
до 5 продаж: самое дорогое творение отмеченной ступени — державе с наибольшим
`bag_rtk_art_accept` (копия ванильной формулы). **Покупатель строже кнопки**
(его требование 10-18): согласие ≥ 1 (число игры `country_interaction_acceptance`
ведёт себя как 0, зонд 0.4.9); после оплаты ≥ 6 месяцев дохода; мнение > 0; не
враг, не соперник. **Продаёт сам** (`add_gold`, престиж −2 %, дипломат,
`move_art_and_owner`): ванильное действие из скрипта не доходит до эффекта
([`testlog_1018_art_action.md`](../../docs/archive/testlog_1018_art_action.md)).
Зонды: `work of art sold, price= quality= accept= buyer gold left=` + имя,
`not sold`, `no buyer for any work of art`. История 10 продаж в игре (работает, цены = ручным): галочка `art_log`, кнопка `art_log_show` → событие `bag_rtk_art.1`.

## Напоминалка об откатах

286 типов отката из `generic_actions` и `country_interactions` — списки CMF
(≤ 50 строк) на четырёх подвкладках (`cmm_register_subtab`: `cd_faith`,
`cd_realm`, `cd_orgs`, `cd_crisis`), по цвету алерта на список;
`tools/gen_cooldowns.py` пишет `bag_rtk_cd_*generated*` и `bag_rtk_cd_l_*.yml`
(после патча — перегенерировать). Религия — `cd_rel1` и `cd_rel2` под одним
именем (второй — Индия, Япония, Америка). Строка видна, если ворота (копия
`potential` и `visible` получателя действия; `= scope:target` снят, выбранная
вера — своя) пропускают, или откат, или галочка, или «Показывать все»; список
без видимых строк прячет его `_on_changed` (`bag_rtk_cd_shown_<список>`). Ворота
— при регистрации, т. е. на каждое открытие меню. Галочка — поле `watch` в
глобальной карте `cmm`. 1-го числа: откат был и кончился → алерт
`bag_rtk_rel_ready_<тип>`, клик убирает и открывает вкладку списка.
Организации — только свои (`is_member_of_international_organization`); в
`visible` получателя `root` и `scope:<target_flag>` — сам кандидат (лига:
`is_member_of_international_organization = root`), копия запоминает его как
`scope:bag_rtk_cd_cand`; для держав-получателей ворота — «есть хоть один»
(`any_country`: действия округов без округов не видны). Империя и император —
свой список `cd_hre` во вкладке организаций; парламентские (`type = parliament`)
не отслеживаются вовсе (его решение 10-19: идут только с парламентом).

Хранилище строк (0.6.4): `bag_rtk_cd_repair_lists` после регистрации сверяет
глобальный список `cmm_list_items_bag_rtk__<список>` с 1..N, пересобирает при
чужой записи или неверном числе (зонд `bag_rtk: list <список> rebuilt, …` в
`debug.log`) и заново пишет переменные строки (подпись, подсказка, владелец — как
`_cmm_initialize_list_item_metadata`). `ERROR_FLAG_INDEX` без галочки (0.6.0,
0.6.3) — строка без этих переменных: 0.6.4 вернул подпись, а галочки не было
без владельца (по нему CMF считает поля строки) → 0.6.5.
Порядок строк стережёт `tools/cd_lists.json`: генератор останавливается, если
старые строки списка — не начало новых.

Сословные действия (`cd_estate`, подвкладка «Держава»): откат у каждого
сословия свой, кроме созыва парламента, а `has_cooldown` сословия не различает,
поэтому строка — пара «действие, сословие» (`ESTATE_ACTIONS` в генераторе), её
ворота — условия действия и выбора сословия, а «на откате» —
`can_do_generic_action = { generic_action = … target = <сословие> }` ложен
(`bag_rtk_cd_check_est`).

Откат модификатором (0.6.3): у 13 действий своего `cooldown` нет, а `allow`
не пускает, пока держится модификатор, который вешает само действие
(«Привлечь чужеземного священнослужителя» — `invited_foreign_cleric_modifier`,
парламентские просьбы, Дели). Их строка следит за `has_country_modifier`
(аргумент `test` у `bag_rtk_cd_gate_row` и `_check_row`) и стоит в конце своего
списка: галочка CMF — по номеру строки, вставка в середину сдвинула бы чужие.

16-летняя невеста «недостаточно близкая родственница правителя». 1-го числа

и без брака с нами) по возрасту, младшие первыми (`bag_rtk_wed_youth`), до пяти
предложений `perform_diplomatic_action = { type = royal_marriage … mode = propose
hidden = yes }`: согласие решает та страна по правилам игры. Женщин — только с
галочкой `wed_women` (по умолчанию вкл.).
