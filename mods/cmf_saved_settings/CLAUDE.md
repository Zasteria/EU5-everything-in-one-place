# `cmf_saved_settings` — брифинг

**Зачем.** Его просьба 10-14: «с каждой новой игрой делать 500 одинаковых
действий в настройках модов». Мод сохраняет все настройки CMF (всех модов, и
чужих) в файл и ставит их обратно в следующей партии.

**Почему через `debug.log`.** Скрипт ничего не пишет за пределы сейва, а CMF
держит значения в карте `cmm` на стране игрока (`global`-настройки — в
глобальной). Единственный выход наружу — `debug_log` (engine.md).
Игра перезаписывает `debug.log` при запуске, поэтому `mods.bat` → 5 уносит блок
`CMFSAVE` в `Documents/.../Europa Universalis V/cmf_saved_settings/`
(файл с датой и `last.txt`). Его просьба 10-14: отдельным файлом.

**Устройство (один мод, 0.3.0; в 0.2.0 применение было отдельным модом
`cmf_my_settings` — «звучит тупо», 10-14, пункт 5 его удаляет):**
1. кнопка «Сохранить» печатает каждую пару `ключ = значение` и порядок
   упорядоченных списков;
2. `mods.bat` → 5 — блок в файл (`last.txt` — только целый блок, с `end`);
3. там же `tools/cmf_saved_apply.py` пишет `bag_cmfs_apply` в
   `bag_cmfs_my_values.txt` **игровой копии** этого мода. В репозитории файл
   пустой (`--stub`), `tree_digest` его не считает, пункт 3 после установки
   пишет его заново из `last.txt`. Крючки статичные (`bag_cmfs_on_actions.txt`).
   Значения пишутся только в партии, начатой с модом
   (`on_game_started_after_lobby` → `bag_cmfs_new_game`), каждый
   ключ один раз и только зарегистрированный (`bag_cmfs_done`), потом
   `cmf_on_callback` на каждую изменённую настройку, как «Сбросить» CMF;
   списки — в сохранённом порядке, места `cmf_dev_beta` сбрасываются. Проходов
   три (новая партия, `on_game_start_after_lobby`, каждая регистрация), потому
   что какой из них идёт после регистрации всех модов — не мерено. В
   `debug.log` — `CMFMY pass applied=N of M`. **`cmm_default` не трогается:**
   регистрация переписывает его каждым проходом, так что «Сбросить» вернёт к
   умолчаниям модов, не к его.

**Почему перенос между державами безопасен.** Регистрация у CM, QoL,
`assimilate_primary`, `cm_perf` одна для любой страны; от страны зависят только
показ и доступность (`is_shown`/`is_valid` скриптового окна). Пункт списка —
постоянный индекс `_i<N>` с регистрации, порядок — отдельный список
`cmm_list_items_<setting>` флагов `<setting>_i<N>`. Риски, которые закладываем:
порядок списков сохраняется по пунктам; значение вне диапазона после обновления
мода пропускается; применение обходит `is_valid` — если он назовёт такие
настройки, их не переносить.

**Формат блока.** `CMFSAVE c|g <число|2> <ключ>` (имя — `GetFlagName` на
глобальной, число — script value; за каждой — `CMFSAVE probe`, обе формы
совпали) и `CMFSAVE order <пункт>` двух списков, между `begin` и `end count=N`.

**Прогоны 10-14:** 0.1.0 — только `begin` (параметр в кавычках); 0.1.1 — 611
строк, после закрытия игры целые (TESTLOG). **0.2.0/0.3.0 — применение, в игре
не было.**

Проверки: `python3 tools/check_cmm.py mods/cmf_saved_settings/in_game/common`,
`python3 tools/check_script.py mods/cmf_saved_settings`.
