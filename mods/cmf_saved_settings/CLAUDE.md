# `cmf_saved_settings` — брифинг

**Зачем.** Его просьба 10-14: «с каждой новой игрой делать 500 одинаковых
действий в настройках модов». Мод сохраняет все настройки CMF (всех модов, и
чужих) в файл и ставит их обратно в следующей партии.

**Почему через `debug.log`.** Скрипт ничего не пишет за пределы сейва, а CMF
держит значения в карте `cmm` на стране игрока (`global`-настройки — в
глобальной). Единственный измеренный выход наружу — `debug_log` (пишет и в
обычной сборке, docs/research/engine.md «What a debug_log string reaches»).
Игра перезаписывает `debug.log` при запуске, поэтому `mods.bat` → 5 уносит блок
`CMFSAVE` в `Documents/.../Europa Universalis V/cmf_saved_settings/`
(файл с датой и `last.txt`). Его просьба 10-14: отдельным файлом.

**Устройство, к которому идём (три части):**
1. кнопка «Сохранить» печатает каждую пару `ключ = значение` и порядок
   упорядоченных списков;
2. `mods.bat` → 5 — блок в файл;
3. **ещё нет:** применение. Локальный мод из файла ставит значения поверх
   умолчаний и в `cmm_default` (так «Сбросить» вернёт к его значениям), в момент
   первой регистрации ключа, и помечает в сейве, что ключ уже поставлен — правки
   посреди партии не перезаписываются, старые сейвы не трогаются.
   **`cmf_on_mod_registration` зовётся при каждом открытии страницы**
   (docs/pitfalls/cmm.md) — пометка обязательна.

**Почему перенос между державами безопасен.** Регистрация у CM, QoL,
`assimilate_primary`, `cm_perf` одна для любой страны; от страны зависят только
показ и доступность (`is_shown`/`is_valid` скриптового окна). Пункт списка —
постоянный индекс `_i<N>` с регистрации, порядок — отдельный список
`cmm_list_items_<setting>` флагов `<setting>_i<N>`. Риски, которые закладываем:
порядок списков сохраняется по пунктам; значение вне диапазона после обновления
мода пропускается; применение обходит `is_valid` — если он назовёт такие
настройки, их не переносить.

**0.1.0 — пробник.** Кнопка печатает строки
`CMFSAVE c|g <число|2> <ключ>` (за каждой — `CMFSAVE probe raw/top`, запасные формы) и
`CMFSAVE order <список> <пункт>` для двух списков (`cm__auto_town_rights_list`,
`bag_asp__priority`), между `CMFSAVE begin 1` и `CMFSAVE end count=N`. Вопрос
прогона — какие из форм печатают: имя через
`GetGlobalVariable(...).GetFlagName` (так выводит свой лог CMF) или `TopScope`,
число через script value (измерено) или `GetValue`.

**10-14, прогон 0.1.0: только `CMFSAVE begin 1`** — параметр, стоявший только
в кавычках. **Прогон 0.1.1 (10-14 08:43): 611 настроек, 609 с именем, 60 строк
порядка из 62, `end` нет** — причина подтверждена, правило в
`docs/pitfalls/cmm.md` и `check_script.py`; `GetFlagName` в `debug_log`
работает. Открыто: хвост лога при открытой игре (не дописан?) и два
безымянных ключа — ждём `last.txt`.
