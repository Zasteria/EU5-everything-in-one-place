# `assimilate_primary` — брифинг (мод «Автоматика совета»)

**0.7.0 (10-12): своя автоматика совета, скелет.** Его просьба 12.10: галочка
в CMF, задания по списку приоритетов, только общие действия; в CMF «Доступные»
(галочка) → «Приоритет» (порядок) → «Тонкие настройки».

**0.6.0 в игре 10-12: раздача работает** — места сменились на интеграцию.
0.7.0 — его просьбы после: имена строк — ссылка игры
`[ShowCabinetActionName('<действие>')]` (как здания CM), вкладка «Тонкие
настройки» (пока список без настроек), номер места (`cmf_dev_beta` +beta8),
порядок интеграции. История 0.1–0.5 — по ссылке внизу.

Как устроено (`tools/council.py`, собирает `tools/generate.py`):
- `POOL` — 20 действий; порядок по умолчанию и пороги — **мои догадки**.
- Галочка выключает игровой «Совет» (`cabinet`) и сразу раздаёт все места.
- **Раздача** (`bag_asp_plan`): сверху вниз по «Приоритету» каждое отмеченное
  действие сначала оставляет за собой места, где оно уже идёт, потом берёт
  свободные — советника с лучшим навыком этого действия (`ordered_cabinet`,
  `order_by = cabinet_member.<adm|dip|mil>`), пока есть цель и свободное место.
  Действие с `allow_multiple` может взять несколько мест. Занятое место
  снимается (`stop_cabinet_action`) перед новым. Что осталось никому не нужным,
  сохраняет своё (в т. ч. действия вне котла).
- Раз в `review` мес. (0 — никогда) — полная раздача; иначе раз в `period` мес.
  — только места без действия.
- Цель проверяется **копией `visible` и `enabled` самого действия** из его
  `select_trigger`; триггеры «другое место уже делает это» сравнивают с `root`,
  у нас это страна — генератор заменяет их переменной `bag_asp_busy_<действие>`
  на занятых целях (ставится и снимается за проход).
- Ассимиляция — в основную культуру, кроме провинций, где признанная ведёт на 30 п. п.
- Месяц — с `cmf_monthly_human_country_pulse` (на нём работает CM), не с
  `monthly_country_pulse`. В `debug.log`: `bag_asp: month` каждый месяц,
  `handing out every seat` / `filling empty seats`, `seat set to <действие>`,
  `a seat is left as it was…`.
- **Интеграция** (его правило 12.10, не настройка): сначала провинция, где
  больше завоёванных районов с основной культурой ≥ 50 % (интегрируются вдвое
  быстрее), потом — с признанной ≥ 50 %, потом по населению (`INTEGRATION`).

**Не проверено:** берёт ли `set_cabinet_action` цели под их
`target_flag` (`selected_province`, `target_1`, `target_religion`… — ваниль
зовёт его только с `target`; с `target` берёт — интеграция, 10-12); работает
ли `order_by = cabinet_member.mil`; порядок `INTEGRATION`; рисует ли строка
`ShowCabinetActionName` с подсказкой игры;
считаются ли `"culture_percentage(dominant_culture)"` и
`order_by = { value = 1 subtract = satisfaction }`; замок места наша
автоматика не видит (`docs/research/vanilla.md`) — запертое место она тоже
переназначит.

Правило основной культуры для **игровой** автоматики (копия
`promote_culture.txt` с условием в `enabled`, порог `LEAD`) и история 0.1–0.4 —
[`docs/archive/assimilate_primary_history.md`](../../docs/archive/assimilate_primary_history.md).
